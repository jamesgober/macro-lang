# macro-lang v1.1.0 — Termination and Resource Bounds

**No macro can hang the expander or exhaust its memory any more.** v1.1.0 gives
every expander a budget — a recursion limit, a cap on expansions, and a cap on
tokens written — that is on by default, closes a way for a macro to escape the
recursion limit by rebuilding its own invocation, and lets repetition
separators carry their definition context like every other template literal.
Every API change is additive: code that builds against 1.0 builds unchanged.

## What is macro-lang?

A hygienic macro expander for language implementations, in the model of Rust's
`macro_rules!` and Scheme's `syntax-rules`, generic over a language's token kind.
A macro is an ordered list of rules over token trees; the expander matches an
invocation against them without backtracking, writes out the first matching
template, and gives every token the template introduces a fresh hygiene
context, so a macro's internal names can never collide with its caller's. It is
`#![forbid(unsafe_code)]`, `no_std`-compatible, and built on `token-lang` and
`intern-lang`.

## What's new in 1.1.0

### `Budget` — bounded work, on by default

Macro input is untrusted, and two lines of macro can describe unbounded work.
The recursion limit alone does not stop it: a macro that doubles its argument
reaches `2^n` tokens at depth `n`, and one that expands into two calls of itself
performs `2^n` expansions, both long before depth 128. Every expander now
enforces a [`Budget`](https://docs.rs/macro-lang/latest/macro_lang/struct.Budget.html):

| Limit | Default | Exceeding it reports |
|---|---:|---|
| `max_depth` | 128 | `ExpandError::RecursionLimit` (unchanged) |
| `max_expansions` | `2^20` | `ExpandError::Budget(Limit::Expansions { max })` |
| `max_tokens` | `2^22` | `ExpandError::Budget(Limit::Tokens { max })` |

`Expander::new` and `Expander::with_limit` apply the defaults, so existing code
is protected without a change. Expansion and token counts accumulate in the
expander's `Usage` until `reset_usage` zeroes them. Tokens are counted one per token, two
per group, plus every token of a substituted capture, and are charged *before*
they are written, so an oversized expansion is refused without being built. A
failed expansion is not charged and leaves the expander exactly as it was.

```rust
use intern_lang::Interner;
use macro_lang::{Budget, Context, ExpandError, Expander, Limit, Macro, Rule, Template};
use token_lang::Span;

let mut names = Interner::new();
let s = Span::new(0, 1);
// three!() => a b c
let three = Macro::new(names.intern("three"), vec![Rule {
    pattern: vec![],
    template: "abc".chars().map(|c| Template::token(c, s)).collect(),
}])?;

let mut expander = Expander::with_budget(Budget::DEFAULT.with_max_tokens(5));
assert!(expander.expand(&three, &[], s, Context::ROOT).is_ok());
assert_eq!(
    expander.expand(&three, &[], s, Context::ROOT),
    Err(ExpandError::Budget(Limit::Tokens { max: 5 })),
);

// Raising the budget lets a long-lived expander continue.
expander.set_budget(expander.budget().with_max_tokens(8));
assert!(expander.expand(&three, &[], s, Context::ROOT).is_ok());
# Ok::<(), Box<dyn std::error::Error>>(())
```

New items: `Budget` (`DEFAULT`, `with_max_depth`, `with_max_expansions`,
`with_max_tokens`, `Default`), `Limit`, `Usage` (`NONE`), `ExpandError::Budget`,
and `Expander::with_budget`, `budget`, `set_budget`, `usage`, `reset_usage`. `Budget`, `Limit`, and
`Usage` are `#[non_exhaustive]`; `ExpandError` already was, so the new variant
is additive.

### Per-unit budgets for long-lived hosts

A batch compiler uses one expander per compilation and never resets. A language
server, REPL, or watch-mode compiler keeps one expander for its whole life and
calls `reset_usage()` once per unit of work — per document parse, per REPL
entry, per rebuild. The budget then bounds each unit, not the process, and one
hostile document cannot use up the budget of the next. The budget, every
minted context, and every `Origin` survive the reset; only the counters are
zeroed.

```rust
use intern_lang::Interner;
use macro_lang::{Budget, Context, ExpandError, Expander, Limit, Macro, Rule, Template};
use token_lang::Span;

let mut names = Interner::new();
let s = Span::new(0, 1);
let one = Macro::new(names.intern("one"), vec![Rule {
    pattern: vec![],
    template: vec![Template::token('k', s)],
}])?;

let mut expander = Expander::with_budget(Budget::DEFAULT.with_max_expansions(2));
for _entry in 0..3 {
    expander.reset_usage(); // a fresh budget per REPL entry
    expander.expand(&one, &[], s, Context::ROOT)?;
    expander.expand(&one, &[], s, Context::ROOT)?;
    assert_eq!(
        expander.expand(&one, &[], s, Context::ROOT),
        Err(ExpandError::Budget(Limit::Expansions { max: 2 })),
    );
}
assert_eq!(expander.usage().expansions, 2);
# Ok::<(), Box<dyn std::error::Error>>(())
```

### `Expander::expand_at` — depth the macros cannot reset

In 1.0 an invocation's depth came only from the context of its name token.
Tokens captured from the input keep their context, so a macro that rebuilt its
own invocation from captured tokens — `m!($a:tt $b:tt) => $a $b ($a $b)`,
invoked as `m!(m !)` — wrote a call identical to the one it came from, ran at
depth 1 every round, and never stopped.

Two changes close this:

- Depth now also follows the **input**: an invocation runs one level below the
  deepest expansion that produced its name token *or any token of its input*.
  A self-rebuilding macro that writes any literal of its own into the call it
  builds is caught by the recursion limit even through plain `expand`.
- `expand_at(mac, input, call_site, call_context, depth)` lets a driver say how
  deep the code it found the invocation in is. A driver that expands each
  output before splicing it (the shape of rustc's expansion collector) passes
  `0` for source and `d + 1` for output of a call made at `d`; the recursion
  limit then holds for every chain of nested expansions, whatever the macros
  reuse.

```rust
use intern_lang::Interner;
use macro_lang::{Context, ExpandError, Expander, Fragment, Macro, Pattern, Rule, Template, Tree};
use token_lang::{Span, Token};

let mut names = Interner::new();
let (n, b) = (names.intern("n"), names.intern("b"));
let tt = |name| Pattern::Bind { name, fragment: Fragment::Tree };
let s = Span::new(0, 1);
// m!($n:tt $b:tt) => $n $b ($n $b)
let m = Macro::new(names.intern("m"), vec![Rule {
    pattern: vec![tt(n), tt(b)],
    template: vec![
        Template::Var(n),
        Template::Var(b),
        Template::Group {
            open: Token::new('(', s),
            close: Token::new(')', s),
            body: vec![Template::Var(n), Template::Var(b)],
        },
    ],
}])?;

let mut expander = Expander::new();
let mut args = vec![Tree::token('m', s), Tree::token('!', s)];
let mut depth = 0;
let err = loop {
    match expander.expand_at(&m, &args, s, Context::ROOT, depth) {
        Ok(out) => match out.get(2) {
            Some(Tree::Group { trees, .. }) => { args = trees.clone(); depth += 1; }
            _ => break None,
        },
        Err(err) => break Some(err),
    }
};
assert_eq!(err, Some(ExpandError::RecursionLimit { limit: 128 }));
# Ok::<(), Box<dyn std::error::Error>>(())
```

Through plain `expand` a call rebuilt *only* from captured source tokens is
indistinguishable from the original — same tokens, same contexts, and group
delimiters carry no context in the frozen `Tree` type — so for that shape the
default budget is what stops it (in about 0.15 s on the benchmark machine).

### `Template::RepeatSeparated` — separators with a definition context

`Template::Repeat`'s separator is a bare token, documented as defined in the
root context. That is exact for a macro written in source, but for a macro
defined by another macro's expansion it split the separator's hygiene from the
other literals of the same definition. The new variant carries the separator's
definition context:

```rust
use macro_lang::{Context, Template};
use intern_lang::Interner;
use token_lang::{Span, Token};

let mut names = Interner::new();
let element: Template<char> = Template::RepeatSeparated {
    body: vec![Template::Var(names.intern("x"))],
    separator: Token::new(';', Span::new(9, 10)),
    ctx: Context::ROOT, // the separator token's own context in the definition
};
assert!(matches!(element, Template::RepeatSeparated { .. }));
```

The separator is marked exactly like a literal defined in `ctx`: it shares the
context the expansion mints for the other literals defined there, and
`Origin::parent` reports `ctx`. `Template::Repeat` is unchanged.

## Behaviour changes

- **Depth can be higher than in 1.0, never lower.** An invocation whose input
  contains tokens from a deeper expansion than its name token now runs below
  that expansion. Ordinary recursive macros (name and literals written by the
  same template) see no change.
- **Caps on one expander.** An expander that performs more than `2^20`
  expansions or writes more than `2^22` tokens without a `reset_usage` now gets
  `ExpandError::Budget`. One expander per compilation stays well inside this;
  a long-lived host calls `reset_usage` per unit of work.

## Performance

The hot path is unchanged within measurement error: a min-of-60-batches A/B
against 1.0.0 on Windows put `list/512` and `nested/64` within 2%. (Criterion
A/B runs on the shared build machine drifted up to 8% between two runs of the
same 1.0.0 binary, too noisy to resolve a few percent; the release gate
re-measures on a quiet machine.) The new benchmarks show that an expansion bomb
costs time linear in the budget, not exponential in depth (criterion means,
x86_64 Windows, release):

| Benchmark | What it measures | Windows |
|---|---|---:|
| `budget/dup/4096` | A doubling macro until a 2^12-token budget stops it. | ~123 µs |
| `budget/dup/16384` | The same, 2^14 tokens. | ~476 µs |
| `budget/dup/65536` | The same, 2^16 tokens. | ~2.7 ms |
| `budget/quine/1024` | A self-rebuilding macro under `expand` until a 2^10-expansion budget. | ~172 µs |
| `budget/quine/16384` | The same, 2^14 expansions. | ~2.7 ms |
| `budget/limit=128` | The same macro under `expand_at`, stopped at depth 128. | ~23 µs |

With the defaults, the doubling macro is stopped in about 0.2 s with a
whole-process peak of about 400 MB, and the self-rebuilding macro under
`expand` in about 0.15 s (release build of `examples/budget`, 8-byte token
kind). Memory grows in proportion to `max_tokens`; lower it where that is too
much.
