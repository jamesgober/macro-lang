# macro-lang v0.2.0 — The Hygienic Expander

**The core, and the hard part of the roadmap.** v0.2.0 turns the scaffold into a
working hygienic macro expander: macros are ordered lists of pattern/template
rules over token trees, matching is a backtracking-free automaton that reports
ambiguity instead of guessing, and every token a template introduces receives a
hygiene context minted for its expansion. The surface is small and
data-oriented — plain enums for patterns and templates, one compiled `Macro`, one
`Expander` — and it is generic over the language's token kind.

## What is macro-lang?

A macro expander for language implementations, in the model of Rust's
`macro_rules!` and Scheme's `syntax-rules`. A language lexes source into tokens,
groups them into token trees, and lowers its own macro-definition syntax into
rules; macro-lang matches invocations against those rules, substitutes captured
trees into templates, and keeps the hygiene record that lets a name resolver
keep a macro's internal names apart from its caller's. It owns no syntax. It is
one of the FEAT-tier crates of the `-lang` language-construction family, built
on `token-lang` and `intern-lang`.

## What's new in 0.2.0

### `Tree` — token trees in, token trees out

Expansion works on token trees: a single `token_lang::Token<K>` with its hygiene
context, or a delimited group. Grouping by delimiters is the one structure every
language has before parsing, and it is what a pattern needs — a group matches as
a unit, and a metavariable can capture a whole bracketed expression without
knowing the grammar inside it.

```rust
use macro_lang::Tree;
use token_lang::{Span, Token};

// f(a)
let call: Vec<Tree<char>> = vec![
    Tree::token('f', Span::new(0, 1)),
    Tree::Group {
        open: Token::new('(', Span::new(1, 2)),
        close: Token::new(')', Span::new(3, 4)),
        trees: vec![Tree::token('a', Span::new(2, 3))],
    },
];
assert_eq!(call[1].span(), Span::new(1, 4));
```

### `Pattern`, `Template`, `Rule`, `Macro` — definitions as plain data

A rule pairs a `Pattern` (literal tokens, groups, `$x:tt`-style bindings,
`*` / `+` / `?` repetitions with optional separators) with a `Template` (literals,
groups, substitutions, lockstep repetitions). `Macro::new` validates and
compiles a list of rules once; every check that does not depend on an
invocation — duplicate or unbound metavariables, wrong repetition depth,
repetitions that could match nothing — is made there, so a macro that builds can
only fail on input.

```rust
use intern_lang::Interner;
use macro_lang::{Context, Expander, Fragment, Kleene, Macro, Pattern, Rule, Template, Tree};
use token_lang::{Span, Token};

let mut names = Interner::new();
let e = names.intern("e");
let s = Span::new(0, 0);

// list!( $($e:tt),* ) => [ $($e);* ]
let list = Macro::new(names.intern("list"), vec![Rule {
    pattern: vec![Pattern::Repeat {
        body: vec![Pattern::Bind { name: e, fragment: Fragment::Tree }],
        separator: Some(','),
        kleene: Kleene::ZeroOrMore,
    }],
    template: vec![Template::Group {
        open: Token::new('[', s),
        close: Token::new(']', s),
        body: vec![Template::Repeat { body: vec![Template::Var(e)], separator: Some(Token::new(';', s)) }],
    }],
}])?;

let input: Vec<Tree<char>> = "a,b"
    .char_indices()
    .map(|(i, c)| Tree::token(c, Span::new(i as u32, i as u32 + 1)))
    .collect();
let out = Expander::new().expand(&list, &input, Span::new(0, 9), Context::ROOT)?;
assert!(matches!(&out[..], [Tree::Group { trees, .. }] if trees.len() == 3)); // a ; b
# Ok::<(), Box<dyn std::error::Error>>(())
```

### Matching without backtracking

Each pattern is compiled into a Thompson-style automaton and simulated in a
single left-to-right pass, with parses that reach the same point merged. There
is no backtracking, so matching cost grows linearly with the input even for
adversarial patterns — `$( $( $x:tt )+ )+` over 20,000 tokens, which has
exponentially many parses, resolves in milliseconds. Merging is also what makes
ambiguity visible: a rule that matches an invocation in two different ways
returns `ExpandError::Ambiguous` instead of silently picking one. Patterns such
as `$($t:tt)* ;`, whose apparent ambiguity the rest of the input resolves, are
accepted. Rules that must begin with a fixed token are rejected on the first
input entry without running the automaton at all.

### Hygiene — `Context`, `Origin`, and `Expander::origin`

Tokens written in source carry `Context::ROOT`. Each expansion mints a context
for the literal tokens its template writes; trees substituted from the
invocation keep the context they arrived with. A resolver that compares spelling
*and* context keeps the two apart, and `Expander::origin` reports where every
minted context came from: the definition-site context to fall back on for free
names, the macro, the call site, and the caller's context for backtraces.

```rust
use intern_lang::Interner;
use macro_lang::{Context, Expander, Fragment, Macro, Pattern, Rule, Template, Tree};
use token_lang::Span;

let mut names = Interner::new();
let x = names.intern("x");
// with_tmp!($x:tt) => t $x  — the template writes its own `t`.
let mac = Macro::new(names.intern("with_tmp"), vec![Rule {
    pattern: vec![Pattern::Bind { name: x, fragment: Fragment::Tree }],
    template: vec![Template::token('t', Span::new(0, 1)), Template::Var(x)],
}])?;

let mut expander = Expander::new();
let out = expander.expand(&mac, &[Tree::token('t', Span::new(9, 10))], Span::new(0, 11), Context::ROOT)?;
let ctx = |i: usize| match &out[i] { Tree::Token { ctx, .. } => *ctx, _ => Context::ROOT };
assert_ne!(ctx(0), ctx(1));           // same spelling, different bindings
assert!(expander.origin(ctx(0)).is_some());
# Ok::<(), Box<dyn std::error::Error>>(())
```

### Bounded recursion

The expander reads an invocation's nesting depth from the context of its name
token, so a macro that expands into a call of itself without a base case stops
with `ExpandError::RecursionLimit` (128 nested expansions by default,
configurable through `Expander::with_limit`) instead of looping.

### Examples, benchmarks, and an oracle

Three runnable examples ship — `hygiene` (the classic `swap!` invoked on a
variable named like its temporary), `vec_literal` (rule selection, separated
repetition, and a caret diagnostic from a failed match), and `recursion` (a
recursive `count!`, a runaway macro stopped by the limit, and an expansion
backtrace). They share a miniature front end that lowers `macro_rules!`-style
text into rules — the template for wiring macro-lang into a real language.

The property tests check the matcher against an independent oracle: a
brute-force counter of every distinct parse. For arbitrary patterns and inputs,
zero parses must mean `NoMatch`, one must mean success, and more than one must
mean `Ambiguous`. On every unique match, a template mirroring the pattern must
reproduce the input exactly.

### Dependency wiring

`token-lang` 1 and `intern-lang` 1 are wired: trees are built from `Token` and
`Span`, and macro and metavariable names are `Symbol`s. `ast-lang` is
deliberately not wired — expansion runs on token trees before parsing, and the
AST is downstream of this crate, not an input to it. The reasoning is recorded
in `dev/ROADMAP.md` under the anti-deferral rule. The scaffold's unused `serde`
feature was removed; serializing trees can return as an additive feature if a
use appears.

### Scaffold fixes

`Cargo.toml` had unquoted `keywords` and `categories`, so the manifest did not
parse at all; `clippy.toml` declared MSRV 1.87 against the crate's 1.85; two docs
carried byte-order marks and CRLF endings; and the README linked a
`dev/DIRECTIVES.md` that does not exist. All are fixed.

## Breaking changes

**None.** v0.1.0 exposed no public API; everything in 0.2.0 is new surface. The
removed `serde` feature had no code behind it.

All green. Counts at this tag (identical for every feature combination):

- 41 unit + 26 integration + 4 property + 63 doctests. The doctests include
  every `rust` example in `README.md` and `docs/API.md`, wired into `cargo test`
  so the published examples cannot drift from the API.

Benchmark baselines (Windows x86_64, release profile, one reused expander):
`list/512` — a separated repetition over 512 elements — runs in ~27 µs
(≈ 52 ns per element, scaling linearly from ~0.54 µs at 8); `nested/64`, two-level
repetition over 64 groups, ~15 µs; `dispatch/rules=16`, sixteen literal-keyed
rules invoking the last, ~0.12 µs; `hygiene/literals=64`, a 64-token template,
~0.54 µs; and `identity/depth=64`, capturing a 64-deep nested group, ~4.0 µs.
