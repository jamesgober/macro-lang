# macro-lang v1.2.0: deep token trees

**Minor.** Token trees nested very deeply no longer overflow the stack inside
the expander or when they are cloned, compared or hashed, and a new
`Tree::dismantle` drops them safely. Code that builds against 1.1 builds
unchanged. MSRV is unchanged at Rust 1.85.

## What changed

The expander already matched and rebuilt trees with explicit work stacks, but
the `Tree` type itself used derived `Clone`, `PartialEq` and `Hash`, which
recurse once per level of group nesting. A few megabytes of `((((...))))` in
source becomes a tree a million levels deep, and walking it that way overflows
the stack.

- **`Clone`, `PartialEq` and `Hash` use a heap stack.** They are now written by
  hand and work at any depth. They behave exactly like the derived impls they
  replace, and `Hash` feeds the hasher the same values in the same order, so
  hash-based collections see no difference. A test holds them to a derived
  mirror type.
- **Failed expansions clean up without recursion.** An expansion that failed
  after writing part of a deeply nested capture, for example by running out of
  its token budget, used to drop that partial output recursively. It is now
  taken apart one group at a time.
- **`Tree::dismantle`** drops any number of trees with a heap stack. Pass one
  tree as `[tree]`, or the `Vec` an expansion returns.

## What did not change

Dropping a `Tree` the ordinary way, and formatting it with `Debug`, still
recurse. `Tree` has public fields that callers move out of by value, and a
custom `Drop` would stop that from compiling, so it can't be added in 1.x. A
front end that builds token trees from untrusted text should cap group nesting
while it builds them, or pass finished trees to `Tree::dismantle` instead of
letting them drop.

## Docs

The `Expander::reset_usage` docs now say plainly that the hygiene table keeps a
record of every expansion and is never shrunk, so its memory grows over the
expander's life. A long-lived host such as a language server should use one
expander per compilation or document version.
