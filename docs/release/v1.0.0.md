# macro-lang v1.0.0 — API Freeze

**The surface is now stable.** v1.0.0 freezes the public API introduced in 0.2.0
under Semantic Versioning and completes the roadmap. The one code change is
preparatory: the definition types and the hygiene record are marked
`#[non_exhaustive]`, so the macro language can keep growing in `1.x` without a
major release.

## What is macro-lang?

A hygienic macro expander for language implementations, in the model of Rust's
`macro_rules!` and Scheme's `syntax-rules`, generic over a language's token kind.
A macro is an ordered list of rules over token trees; the expander matches an
invocation against them without backtracking, writes out the first matching
template, and gives every token the template introduces a fresh hygiene
context, so a macro's internal names can never collide with its caller's. The
surface is [`Tree`](https://docs.rs/macro-lang/latest/macro_lang/enum.Tree.html),
[`Pattern`](https://docs.rs/macro-lang/latest/macro_lang/enum.Pattern.html) /
[`Fragment`](https://docs.rs/macro-lang/latest/macro_lang/enum.Fragment.html) /
[`Kleene`](https://docs.rs/macro-lang/latest/macro_lang/enum.Kleene.html),
[`Template`](https://docs.rs/macro-lang/latest/macro_lang/enum.Template.html),
[`Rule`](https://docs.rs/macro-lang/latest/macro_lang/struct.Rule.html),
[`Macro`](https://docs.rs/macro-lang/latest/macro_lang/struct.Macro.html),
[`Expander`](https://docs.rs/macro-lang/latest/macro_lang/struct.Expander.html),
[`Context`](https://docs.rs/macro-lang/latest/macro_lang/struct.Context.html) /
[`Origin`](https://docs.rs/macro-lang/latest/macro_lang/struct.Origin.html), and
two error enums. It is `#![forbid(unsafe_code)]`, `no_std`-compatible, and built
on `token-lang` and `intern-lang`.

## The stability promise

As of 1.0.0 the public API is frozen. Within the `1.x` series:

- The surface will not change in a breaking way. A breaking change means a new
  major version.
- The **matching semantics** are part of the contract: rules are tried in order
  and the first whose pattern matches the entire invocation wins; literal tokens
  compare by kind only; a rule that matches in more than one way is reported as
  `Ambiguous` and stops the search; matching never backtracks; and `NoMatch`
  points at the furthest point any rule reached.
- The **hygiene semantics** are part of the contract: each expansion mints fresh
  contexts for the literal tokens and separators its template writes, captured
  trees keep their contexts, `Origin` records the definition context, macro,
  call site, and call context, nesting depth is read from the call context, and
  a failed expansion leaves the expander unchanged.
- The definition checks in `Macro::new` are fixed: a macro that builds under
  `1.0` keeps building under every `1.x`. `Expander::DEFAULT_LIMIT` stays `128`.
- `Pattern`, `Fragment`, `Template`, `Origin`, `MacroError`, and `ExpandError`
  are `#[non_exhaustive]`; new elements, fields, and failure modes are additive
  minor changes. Match them with a wildcard arm.
- MSRV (Rust 1.85) is a compatibility surface: raising it is a documented minor
  change, never a patch.

Not promised: the exact `Display` wording of the errors, any `Debug` output, the
compiled representation of a `Macro`, and performance figures.

Full details in [`docs/API.md`](https://github.com/jamesgober/macro-lang/blob/main/docs/API.md#stability).

## Since 0.2.0

`Pattern`, `Fragment`, and `Template` are now `#[non_exhaustive]`, and so is
`Origin`. This keeps the definition language open to additions — metavariable
expressions in templates, new fragment kinds — and the hygiene record open to
new fields, all without a major release. Construction is unaffected:

```rust
use intern_lang::Interner;
use macro_lang::{Fragment, Kleene, Macro, Pattern, Rule, Template};
use token_lang::{Span, Token};

let mut names = Interner::new();
let x = names.intern("x");

// Building patterns and templates works exactly as in 0.2.0.
let mac: Macro<char> = Macro::new(names.intern("m"), vec![Rule {
    pattern: vec![Pattern::Repeat {
        body: vec![Pattern::Bind { name: x, fragment: Fragment::Tree }],
        separator: Some(','),
        kleene: Kleene::ZeroOrMore,
    }],
    template: vec![Template::Repeat {
        body: vec![Template::Var(x)],
        separator: Some(Token::new(';', Span::new(0, 1))),
    }],
}])?;
assert_eq!(names.resolve(mac.name()), Some("m"));
# Ok::<(), macro_lang::MacroError>(())
```

Code that *matches* on these enums now needs a wildcard arm, and code that
destructures an `Origin` needs a trailing `..`:

```rust
use intern_lang::Interner;
use macro_lang::{Context, Expander, Fragment, Macro, Origin, Rule, Template, Tree};
use token_lang::Span;

fn describe(fragment: &Fragment<char>) -> &'static str {
    match fragment {
        Fragment::Tree => "tt",
        Fragment::Kind(_) => "a token class",
        _ => "another fragment kind", // required now that Fragment is non-exhaustive
    }
}
assert_eq!(describe(&Fragment::Tree), "tt");

let mut names = Interner::new();
let mac = Macro::new(names.intern("t"), vec![Rule {
    pattern: vec![],
    template: vec![Template::token('t', Span::new(0, 1))],
}])?;
let mut expander = Expander::new();
let out = expander.expand(&mac, &[], Span::new(4, 9), Context::ROOT)?;
let Some(Tree::Token { ctx, .. }) = out.first() else {
    return Err("expected one token".into());
};
let Origin { call_site, .. } = expander.origin(*ctx).ok_or("not minted here")?; // `..` required
assert_eq!(call_site, Span::new(4, 9));
# Ok::<(), Box<dyn std::error::Error>>(())
```

Nothing else changed. Moving from `macro-lang = "0.2"` to `"1"` is a recompile
for any code that only builds definitions and reads results.

## Performance

Unchanged from 0.2.0. Criterion means, x86_64, Rust stable, release build, one
reused expander:

| Benchmark | What it measures | Windows | Linux (WSL2) |
|---|---|---:|---:|
| `list/8` | `$($e:tt),* => [$($e);*]` over 8 elements. | ~0.56 µs | ~0.53 µs |
| `list/512` | The same over 512 elements. | ~27 µs | ~26 µs |
| `nested/64` | `$( ( $($x:tt)* ) )*` over 64 groups of four tokens. | ~16 µs | ~13 µs |
| `dispatch/rules=16` | Sixteen rules keyed by a leading token, invoking the last. | ~0.13 µs | ~0.09 µs |
| `hygiene/literals=64` | A template writing 64 literal tokens, each marked. | ~0.56 µs | ~0.31 µs |
| `identity/depth=64` | `$($t:tt)*` capturing a 64-deep nested group. | ~4.7 µs | ~3.2 µs |

Expansion cost grows linearly with input length — about 50 ns per element for a
separated list — and stays linear for adversarial patterns, since the matcher
never backtracks. Numbers vary by CPU; run `cargo bench --bench bench` on your
target for a baseline.
